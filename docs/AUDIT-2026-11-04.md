# Focused security, correctness and performance audit — 2026-11-04

Baseline: published `9874ad582acf632b8916ecad4736d19e759b5312`.
Audited implementation and measured source: clean
`61283baabd8088446b0b69c1febccf98dffe1241`.

Two independent reviewers inspected native process/filesystem boundaries and
Goose dependency/source/CLI/bootstrap behavior. Confirmed findings were fixed
and independently rechecked. No remaining blocking finding was reported in this
scope. This bounded review does not certify security, stability or Cargo parity.

## Fixes and regression evidence

- **Deep source cleanup:** copying accepts source directories at depth 64, but
  cleanup counted generated staging wrappers against the same limit. Subsequent
  checks and clean could fail on accepted trees. A bounded cleanup allowance
  covers private wrappers and file leaves. Repeated check/package/clean at depth
  64 and cleanup after rejecting depth 65 now pass.
- **Formatting limits:** one argv containing 4,096 supported sources exceeded
  the subprocess argument count; long paths could also exceed its byte limit.
  Ordered batches hold at most 256 files and 64 KiB of packed arguments.
  Regression coverage formats/checks 4,096 files whose aggregate paths exceed
  1 MiB. An empty source list now returns without invoking the compiler's
  implicit stdin formatter.
- **Git TLS policy:** inherited `GIT_SSL_NO_VERIFY` bypassed certificate checks.
  Honk clears it and forces both generic and exact-URL verification, including
  URL-specific cache overrides. Real TLS probes generate temporary certificates
  and keys, verify untrusted/wrong-host rejection, permit a trusted fixture to
  reach HTTP, and confirm HTTPS-to-HTTP redirects never contact the HTTP server.
  An `=` in the fixture URL path covers exact-URL config argument encoding.
  System trust roots and Git CA environment settings remain usable. Git 2.31+
  is now required for `--config-env`.
- **Standalone bootstrap policy:** ambient Git configuration could execute a
  checkout hook. Bootstrap now applies the application policy, fetches the fixed
  reviewed HTTPS upstream independently of cached origin, validates the full
  pin before use and checks HEAD before CMake. The offline regression uses real
  Git checkout/config/hook handling with only the network endpoint substituted
  by a local repository and CMake made inert.
- **Metadata:** `-p`/`--workspace` were silently ignored, and a non-UTF-8 POSIX
  project path could produce successful malformed JSON. Selection now returns
  one object or a streamed workspace array without creating caches or obtaining
  a compiler. Missing/ambiguous selections, unsafe members and invalid UTF-8
  roots fail explicitly. Consumers must check status before using streamed output.

The full suite passes 56 CLI integration cases, Goose JIT/native core contracts,
process probes and 213 deterministic malformed-import probes plus FIFO rejection.
Both GCC 16.2.1 and Clang 23.1.4 passed ASan/UBSan with leak detection, Goose debug
checks and bounds-check elimination disabled; forced portable-copy suites pass
on both compilers. Clang static analysis reports no diagnostics. CI now runs
GCC and Clang sanitizer/portable-copy jobs. Test fixture keys are temporary and
are not checked in.

## Paired measurements

All samples use the same pinned Goose compiler/runtime and build method as
[the publication results](../RESULTS.md): default optimized C backend (`-O2`),
GCC 16.2.1, Intel Core Ultra 7 258V, Linux 7.2.11-arch1-1/glibc 2.44.
Processes were pinned to logical CPU 1 on a shared machine. Compiler bootstrap
validation on other cores and unrelated host activity can affect shared
resources; these are local observations, not universal rankings or guarantees.
The paired harness alternates execution order, with nine samples per binary
and workload, after warmup. Fixture creation is outside timing. There is no
network in the timed workload and no acceptance threshold.

Reproduce with [bench/README.md](../bench/README.md), setting `HONK` to the
reviewed optimized binary, `HONK_BASELINE` to an optimized binary built from the
baseline, `HONK_BASELINE_REVISION` to the full baseline SHA and `AUDIT_SAMPLES=9`.
Leave `AUDIT_TEMP_ROOT` unset for tmpfs or set it to a btrfs directory for that
workload. `AUDIT_REPORT` selects the output JSON. Use `taskset -c 1` for the
recorded affinity. The raw files retain every sample, both binary hashes,
compiler/runtime, clean source revision, CPU and filesystem:
[tmpfs](../bench/results/deep-audit-tmpfs.json),
[btrfs](../bench/results/deep-audit-btrfs.json).

## Standalone and hosted verification

A fresh public HTTPS clone of the measured source completed a cold `make setup`
with inherited `GIT_SSL_NO_VERIFY=1`, then `make check test security build`,
self-packaging with `--frozen` and the README sibling application `new`, `run`,
`check --frozen` workflow. The checkout stayed clean. The bootstrap compiler
was built from its exact full pin; Honk did not reuse the development compiler.

The exact-source [hosted CI run passed both GCC and Clang jobs](https://github.com/carabistouflette/honk/actions/runs/41811008239),
including setup, all checks/tests/security probes, sanitizers, forced portable
copies and benchmark execution. Later audit-report commits add evidence and
strengthen existing test assertions without changing the measured application.

## Remaining boundaries

Honk builds trusted projects with trusted tools. It does not sandbox native
code, supervise arbitrary grandchildren, impose universal command deadlines,
provide signed toolchain distribution, or implement a registry/semver solver.
Private project/cache directories must not be writable by untrusted users.
See [SECURITY.md](../SECURITY.md). No sibling library or parent repository pin
changed during this audit.
